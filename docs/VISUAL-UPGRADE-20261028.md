# 시나리오·2D 탐구 무대 고도화

갱신: 2026-10-28. 이전 채팅의 중단된 요청(PRD·TRD 갱신 + 핵심 CSS/이모지 그림 교체)을 이어서 수행했다. 스테이지 흐름 개선은 유지했다. 추가 요청에 따라 미리보기를 열고 사용자 제공 프로젝트와 비교한 뒤 게임 폴리시를 적용했다.

## 비교 근거와 차이

[운영시트](https://docs.google.com/spreadsheets/d/1wtMAgkMfvhC30iwLCPC4PV_rkqtrHtwMVlsafSN_dxo/edit?gid=272424340)의 ‘이예리 선생님’ 탭 A1:J55에서 프로젝트 링크를 읽었다. 시트는 수정하지 않았다. 다음 세 사이트의 메인·지도·실제 첫 활동을 브라우저에서 확인했다.

- [동물기록 복구작전](https://animal-record-recovery.yelsam.workers.dev/): 전체 배경·큰 표본·관찰 노트, 가장자리의 작은 메뉴.
- [초록정원 연구기지](https://leafy-garden.pages.dev/): 자연 공간·큰 잎과 도구·캐릭터 안내, 종이색 패널.
- [방울이의 물길탐험](https://water-state-lab.pages.dev/): 큰 실험 대상·직접 조작·작은 상단 표지판과 도구.

기존 화면은 웹사이트형 브랜드 헤더, 작은 그림 카드, 여러 겹의 흰 패널 비중이 컸다. 단순히 이모지를 삽화로 바꾼 뒤에도 대상이 작게 갇혀 보였다. 따라서 배경/대상 비율·메뉴 위계·패널 색과 테두리·캐릭터 안내를 함께 수정했다. 참고작의 실시간 3D 표본은 가져오지 않았다. 사용자 결정인 ‘지도만 2.5D 픽셀아트, 활동은 2D’를 우선했다.

## 변경

| 영역 | 이전 | 변경 |
|---|---|---|
| 메인·활동 메뉴 | 가로 브랜드 헤더·장 표시 | 작은 가장자리 메뉴, 간결한 크림색 제목 표지판 |
| 활동 무대 | 흰 패널과 작은 이모지 | 큰 2D 삽화·자연 배경·따뜻한 종이 패널 |
| P01·P02 | 이모지 표본·관찰 지점 표시 | 실제 풀·햇빛·물·버섯과 분류 삽화 |
| P03·P04 | 역할 이모지·CSS 흙띠·낙엽 이모지 | 역할 삽화·흙 단면·실제 낙엽 축적 그림 |
| P05·P06·P10 | 먹이 노드 이모지 | 통일된 생물 삽화. 실시간 관계선과 조작은 유지 |
| P07·P08 | 배경 색·이모지로 오염/보전 표현 | 같은 구도의 변화 전·방치 후·보전 후 장면 |
| P09 | 같은 배경에 색 변화 | 실행한 대책과 남은 대책을 구분, 실제 계산 지표 유지 |
| 엔딩 | 이모지 동물 | 2D 복원 풍경·생물 삽화·모아 |
| 연결·완료 | 상태 변경 중심 | 짧은 대상/기록 강조. 판정·저장은 연출과 분리 |

학습 정답·예산·해금·자동 기록·저장 키는 바꾸지 않았다. 그림에 글자나 화살표를 굽지 않았다. 모바일/좁은 창은 세로 흐름을 허용하고 주요 버튼은 44px 이상 유지했다.

## 게임 피드백 진단

적용 스킬: imagegen, edu-webapp, game-feel-polish. 공격·피격·전투는 해당 없음이다.

| 사건 | 문제와 빈 구간 | 처리·강도 |
|---|---|---|
| 일반 입력 | 결과와 입력 대상의 연결이 약함 | 즉시 선택/눌림/포커스 반응 유지, 눌림 위치 2px 이동 |
| 먹이 연결 | 관계선은 생기지만 연결 도착점의 변화 인지가 약함 | 선 생성·기존 연결음 뒤 대상 380ms 강조. 일반 사건 |
| 활동 완료 | 마지막 조작에서 기록 위치로 주목이 이어지지 않음 | 완료 패널과 조사 기록 650ms 강조. 중요 사건 |
| 최종 성공 | 화면 전체가 CSS 장면에 의존 | 복원 풍경·선택 대책 결과·인증서로 연결. 기존 가동/충격/수정 조건 유지 |

유지: 기존 효과음·에너지 흐름·자동 기록·타이머 정리·오답 피드백. 통합: 공통 삽화 경로/마크업과 연결·완료 시각 피드백. 삭제/교체: 런타임의 핵심 개념 이모지 출력·P08 단색 오염 레이어·P09 같은 결과 풍경. 새 연출은 모션 감소 설정을 존중하며 진행을 지연하지 않는다.

## 에셋

내장 image_gen으로 총 18개 최종 WebP를 준비했다. 중단 전 생성된 메뚜기·개구리 두 장을 복구하고 나머지 16개를 생성했다. CLI 모델 폴백은 사용하지 않았다.

- 사용본: assets/learning-v2/ (투명 대상 256×256, 물가 장면 1280×720).
- 원본·크로마키 처리본·출처·정확한 최종 프롬프트 세트: asset-bank/learning-v2/generation-manifest.json과 같은 폴더.
- 투명 대상은 단색 키 배경 → 공식 remove_chroma_key.py → 알파 확인 → WebP 변환을 사용했다. 기존 투명 메뚜기·개구리는 알파를 보존했다.
- 식물·메뚜기·애벌레·개구리·참새·뱀·나무·버섯·물·햇빛·흙·낙엽·오염원 줄이기·하천 정화·묘목·물가 세 장면.
- 전체 새 이미지 합계 약 1.26 MiB. 메인 첫 화면에는 신규 학습 에셋을 요청하지 않는다. 페이지별로 쓰는 URL만 렌더한다.
- UI·관계 화살표·접근성 이름은 DOM/SVG로 유지한다. 원본은 삭제하거나 덮어쓰지 않았다.

## 코드·문서

## 검증 근거

- npm run check, npm test (18/18), npm run build 통과.
- 별도 dist 서버 4188과 QA 브라우저로 검사해 사용자 미리보기 4187의 기록을 초기화하지 않았다.
- 1366×768·1024×768·1280×720에서 P01~P10 총 30화면의 가로 넘침, 활성 주요 버튼 44px 미만, 깨진 img, 미치환 템플릿 글자를 검사했다. 발견 0건.
- P10은 보고서뿐 아니라 10개 요소 배치·관계 연결·대책 선택 화면을 검사했다.
- P04 예상 → 자동 시간 진행 → 분해자 제거/낙엽 축적 → 복원 → 설명 → 자동 기록 → 새로고침 보존 확인.
- P08 두 조건의 전후 네 장면 → 설명 → 자동 기록 확인.
- P09 실제 선택한 3개 대책 강조와 미선택 묘목의 ‘다음에 돌볼 곳’, 이유 선택 → 자동 기록 확인.
- P10 필수 대책 누락 실패 → 수정 → 기본 성공 → 메뚜기 부재 실패 → 애벌레 대체 경로 두 개 연결 → 재통과 → 엔딩 → 인증서 → 새로고침 보존 확인.
- 브라우저 오류 로그 0건. 발견한 빈 무대의 미치환 템플릿과 선택 탭 대비 문제는 수정하고 재확인했다.
- 키보드 Enter로 먹이 관계를 연결하고, 모션 감소 모드에서 관계선은 남고 에너지 점은 생성되지 않는 것을 확인했다.
- 정상 삽화가 추가되자 기존 ‘모든 img 태그 금지’ 보안 검사가 오탐을 냈다. 저장된 악성 시험 기록의 원문 태그·onerror 속성 실행을 차단하고 정확히 이스케이프되는지를 검사하도록 수정했고 18개 검사가 통과했다.
- Graphify 그래프가 없고 CLI가 설치되지 않아 graphify update는 실행할 수 없었다.

실제 태블릿·전자칠판·학교망 30대 동시 접속·인쇄물·외부 배포는 확인하지 않았다. 일부 화면은 세로 스크롤을 사용한다. 이 기록은 로컬 부분 개선 검증이며 전체 납품 QA 완료를 뜻하지 않는다.
