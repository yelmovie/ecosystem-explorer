# 14번 생명의 그물 지도 · 첫 화면 로딩 개선

첫 화면의 모아·도토 소개와 탐험 시작 흐름을 유지했다. 지도에 들어가면 지도 코드와 배경·캐릭터 그림을 동시에 요청한다. 첫 활동에 들어가면 활동 화면·조작 코드와 전용 스타일을 받는다. 생태 설계 미션과 교사용 안내도 각각 열 때 불러온다.

지도 코드가 실패하면 **다시 열기**로 현재 지도 주소를 새로고침한다. 그림만 실패하면 지도 자료만 다시 요청한다. **첫 활동 시작**은 지도 코드나 그림을 기다리지 않고 관찰 활동으로 연결한다. 기존 진행 기록이 있는 경우에는 그 시점에 열려 있는 다음 활동을 안내한다.

| 지표 | 로컬 전 → 후 | 느린 환경 전 → 후 |
| --- | ---: | ---: |
| 접속 → 시작 버튼 조작 가능 | 40 → 31 ms | 894 → 531 ms |
| 첫 내용 표시(FCP, 초기 안내 포함) | 28 → 28 ms | 384 → 340 ms |
| 첫 화면 주요 콘텐츠 표시(LCP) | 68 → 60 ms | 1,588 → 1,392 ms |
| 시작 버튼 → 지도 그림·캐릭터 준비 | 106 → 107 ms | 801 → 838 ms |
| 지도에서 다음 활동 선택 → 첫 관찰 조작 가능 | 31 → 64 ms | 61 → 311 ms |

변경 전 소스 스냅샷과 변경 후 배포용 정적 빌드를 같은 Mac의 로컬 서버에서 비교했다. Chrome 1280×800, 동작 줄이기, HTTP 캐시 끄기, 조건별·버전별 5회 교차 실행의 중앙값이다. 느린 환경은 다운로드 10 Mbps, 지연 40 ms, CPU 4배 감속을 적용했다. 첫 화면의 JS/CSS 요청 수는 36 → 15개였다. 압축 전 JS는 210 → 92 kB, CSS는 232 → 168 kB였다. 지도 화면에서 활동 코드가 내려오지 않는 것도 확인했다.

- 지도 JS와 지도 그림을 각각 차단했다. 차단을 풀고 재시도하면 지도를 거쳐 첫 활동에 들어갔고, 차단을 유지하면 지도 없이도 풀·물·햇빛·버섯 관찰 네 건을 터치로 완료할 수 있었다. 새로고침 뒤에도 완료 기록이 남았다.
- 지도 JS와 그림 응답을 각각 보류한 경우 약 10.3초, 20.4초 뒤에 실패 안내가 나왔고 그 상태에서 첫 활동으로 이동할 수 있었다. 지도 로딩 도중 홈에 갔을 때 늦게 끝난 요청이 홈 화면을 덮지 않았다.
- 생태 설계 미션과 교사용 안내가 지도·활동 진입 없이 열리는지, 미션을 키보드로 닫으면 원래 버튼으로 초점이 돌아오는지 확인했다.
- 정적 배포 빌드, 구문 검사, 단위 테스트 66개, 브라우저 자동재생 회귀 검사 12항목, `git diff --check`가 통과했다. 기존 전체 탐험 스크립트는 변경 전후 모두 P02 완료 뒤 곧바로 P03으로 이동한다고 가정해 멈췄다. 실제 화면처럼 짝수 활동 뒤 지도를 거치도록 조정한 임시 검사에서는 10개 활동과 인증서까지 완료했고 브라우저 오류와 실패 응답은 없었다. 운영 주소는 유지했고 배포하지 않았다.
