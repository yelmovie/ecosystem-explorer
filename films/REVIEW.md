# 개념영상 10편 · 「모아의 탐사 노트」 검토 (2026-11-09)

## 만든 방식

- 구조: `films.data.mjs`(편별 장면) + `kit/`(공용 부품·노트 종이·이름표·화살표·제거 표시·모아 세 자세·결론 한 줄) → `build.mjs`가 `films/pNN/`(HyperFrames 프로젝트)을 만들고 `render.mjs`가 렌더해 앱 경로(`assets/concepts/pNN.mp4`, `pNN.jpg`)로 옮긴다.
- 시간표 하나: 모든 편 15초, 장면 경계 0 / 5 / 10초. `src/learning.js`의 `conceptClock`이 영상 장면, VTT 자막(`scripts/make-vtt.mjs`), 앱의 자막 강조·장면 버튼, 모달의 "15초" 표기를 함께 구동한다. `tests/concept-timing.test.mjs`가 learning ↔ VTT ↔ mp4 길이를 대조한다.
- 흐름(편마다 한 생각): 질문(제목) + 방금 한 실험의 처음 상태 → 바뀌는 순간과 확대(punch-in 1회) + 바뀐 물체 위 이름표 → 결론 한 줄 + 모아 반응(돋보기 → 가리키기/놀람 → 환호).
- 그림: 게임 안의 학습 삽화(assets/learning-v2) 18장, 하천 전·후 장면 3장, 모아 자세 시트(돋보기·가리키기·놀람·환호·물고기)를 잘라 썼다. 새로 생성한 이미지는 없다. 화살표·제거 표시·이름표·틀은 SVG/CSS.
- 소리: 음악 없음. 행동마다 효과음 하나(게임의 Kenney CC0: 놓기 drop, 이름표 pluck, 바뀜 switch, 확대 maximize, 결론 confirmation). 내레이션 없음.
- 생태 변화 표현: 상대단계만(처음 / 분해자 제거 후 / 복원 후, 대책 없이 / 보전 대책). P09의 상태어(돌봄 필요·개선 중·좋아짐)는 게임 모형(`recovery()`)이 같은 작전에 내는 값과 같다. 숫자·막대 값·회복 일수 없음.

## 측정한 것

- `hyperframes check` 10편 모두 오류 0. 남긴 경고와 이유:
  - `nested_structure_needs_subcomposition`: 부품마다 바깥 clip(타이밍) + 안쪽 요소(움직임)로 나눈 의도된 구조. 한 장면 한 파일 구조가 아니라 공용 부품을 데이터로 찍는 방식이라 그대로 둔다.
  - `font_face_local_only`: 한글 글꼴을 이 맥의 Apple SD Gothic Neo로 그렸다(게임 UI와 같은 글꼴). 클라우드 렌더는 하지 않으므로 유지. 재배포 가능한 한글 글꼴 파일은 저장소에 없다.
  - `duplicate_media_discovery_risk`(P04·P08): 같은 그림을 다른 시각에 다시 쓰는 장면(낙엽 두 무더기, 변화 전 하천 두 번). 렌더 결과에 영향 없음.
  - info `canvas_overflow`/`container_overflow`: 확대(punch-in) 중 순간 판정.
- snapshot으로 편마다 3.9 / 8.8 / 14.9초를 보고 고친 것: P03 소비자·분해자 이름표 겹침, P04 단계 칩이 확대 때 화면 밖으로 밀림(칩을 확대 바깥층으로), P04 복원 뒤 "낙엽이 쌓여"가 남던 것, P05 두 이름표 맞닿음, P06 5~10초 정지 구간(뱀까지 가는 길 질문 추가), P10 단계 칩과 이름표 겹침.
